# SuperKernel Composer Source Reference Plugin

包：[`super-kernel/composer-source-reference-plugin`](https://github.com/super-kernel/composer-source-reference-plugin) · [Packagist](https://packagist.org/packages/super-kernel/composer-source-reference-plugin) · [文档索引](../README.zh-CN.md)

## 用途

Composer 为从本地 `path` 仓库安装的包提供的引用不会随包的源码变化，因此 `composer.lock` 可能保持不变，而它背后的代码已经变了。`super-kernel/composer-source-reference-plugin` 为 `super-kernel/*` 路径包把这个引用替换为由包的生产源码计算出的引用。这样源码的变化就会改变 `composer.lock`，所有信任该锁文件的东西（例如 `skernel build` 的构建元数据）都会看到这个变化。

该插件只在 Composer 内部、在 `composer update` 期间工作。从 Packagist 安装的包、根包以及其他供应商的包都不受影响，应用启动时也不会扫描任何源码。

## 能力

### 使用来自路径仓库的本地包

在安装路径包的项目中依赖该插件，并在 `config.allow-plugins` 中允许它。路径包从其目录获取版本（例如主分支的检出为 `dev-main`），因此请用接受该版本的约束（例如 `*`）依赖它。

项目的清单，保存为 `composer.json`，其中 `../packages/filesystem` 是一份 `super-kernel/filesystem` 副本：

```json
{
    "name": "acme/billing",
    "type": "project",
    "repositories": [
        {
            "type": "path",
            "url": "../packages/filesystem"
        }
    ],
    "require": {
        "super-kernel/composer-source-reference-plugin": "^1.0.0-alpha.2",
        "super-kernel/filesystem": "*"
    },
    "minimum-stability": "dev",
    "prefer-stable": true,
    "config": {
        "allow-plugins": {
            "super-kernel/composer-source-reference-plugin": true
        }
    }
}
```

Composer 只有在插件安装之后才加载它，而插件必须在 Composer 构建依赖池之前加载。因此引入该插件需要两次更新：第一次安装它，第二次计算引用。此后每次 `composer update` 都会同时完成两者。

```bash
composer update
composer update
```

随后 `composer.lock` 记录该路径包，其 `dist.reference` 为 `sk-source-v1-` 加上 64 个十六进制数字，例如：

```text
sk-source-v1-7681e1c9d13c586b0e646fead9ad081cdfe5440425fde9f384062aa9c4ec63f5
```

### 了解哪些包计入

每次更新期间，只有满足以下全部条件的包才会被插件处理：

- 名称以 `super-kernel/` 开头；
- 来自 `path` 仓库，具有非空的 URL 和原始引用；
- 本次更新解析了它：被本次更新保持锁定或固定的包（例如没有在 `composer update <package>` 中指定的包）以及别名，保持其当前引用。

### 了解哪些文件计入

引用是对以下内容计算的哈希：

- 包名；
- Composer 为路径仓库计算的引用，因此对包的 `composer.json` 或仓库选项的修改仍会改变结果；
- 包的生产 `autoload` 规则通过 `psr-0`、`psr-4`、`classmap` 和 `files` 到达的每个文件，取其相对于包的路径和字节，并按路径排序。

被 `exclude-from-classmap` 匹配的文件不计入 `psr-0`、`psr-4` 和 `classmap`。包的 `autoload-dev`、测试、文档以及任何生产规则都没有到达的文件都不计入。检出的绝对位置、文件时间、inode 数据以及文件系统列出目录的顺序都不会影响结果，因此相同的源码在每台机器上都得到相同的引用。插件已经生成的引用会被识别出来，不会再次计算哈希，因此重复更新是稳定的。

### 在锁文件中看到源码的变化

修改路径包的某个生产源文件之后，更新该包会写入一个新的引用。恢复该文件会恢复之前的引用；修改生产规则之外的文件（例如文档）则不会改变任何东西。

```bash
composer update super-kernel/filesystem
```

### 更新之后重新构建

`skernel build` 生成的元数据记录了 `composer.lock` 的哈希。新的引用会改变锁文件，因此下一次启动会抛出 `SuperKernel\Metadata\Exception\BuildRequiredException`，其消息为 ``The metadata generated by SKERNEL <version> does not match the current composer.lock. Run `skernel build` to generate the project metadata.`` 请在更新之后运行 `skernel build`，或者用会先构建的 `skernel run` 启动。本地包中的变化就是这样在启动时无需任何扫描而到达应用的。

### 绕过插件

`composer update --no-plugins` 不会加载插件，因此 Composer 会再次写入它自己的路径引用，锁文件不再跟随源码变化。`composer install` 安装锁文件中已有的引用。

## 错误

插件会使更新失败，而不是根据部分扫描写入引用。每个错误都是一个由 Composer 报告并中止更新的 `RuntimeException`。

| 情形 | 消息 |
| --- | --- |
| 包含空字节的自动加载路径 | `Autoload paths must not contain null bytes.` |
| 绝对的自动加载路径 | `Autoload path "<path>" must be package-relative.` |
| 包含 `..` 的自动加载路径 | `Autoload paths must not contain ".." segments.` |
| `*` 以外的通配符，或者 `classmap` 之外的通配符 | `Classmap paths support only the "*" wildcard.` 或 `Only classmap paths may contain the "*" wildcard.` |
| 解析到包之外（例如通过符号链接）的自动加载路径 | `Autoload path "<path>" resolves outside package root "<root>".` |
| 不是普通文件的 `files` 条目 | `Autoload file "<path>" is not a regular file.` |
| 不是数组的 `autoload` 字段，或者包含非字符串条目的列表 | `autoload.<field> must be an array.` 或 `<context> must contain only strings.` |
| 无效的 `exclude-from-classmap` 模式 | `Invalid classmap exclusion pattern "<pattern>".`、`Classmap exclusion patterns must not contain null bytes.` 或 `Classmap exclusion patterns must not contain ".." segments.` |
| 无法读取的 classmap 模式或源码目录 | `Unable to expand classmap pattern "<path>".` 或 `Unable to scan source directory "<path>".` |
| 无法读取的源文件 | `Unable to hash source file "<path>".` |
| 路径包的目录不存在 | `Path package directory "<url>" is unavailable.` |

缺失的可选包含项（例如不存在的 `psr-4` 目录）不贡献任何文件，也不是错误。

## 与其他包的关系

- [`super-kernel/metadata`](metadata.zh-CN.md) 把 `skernel build` 记录的 `composer.lock` 哈希与当前的锁文件比较，二者不同时抛出 `BuildRequiredException`。
- `skernel build` 根据更新后的锁文件重新生成元数据；`skernel run` 在启动应用之前先构建。
- 该插件不依赖任何其他 SuperKernel 包，也没有 SuperKernel 包依赖它；它服务于从本地路径安装 SuperKernel 包的项目。

## 不要这样做

**不要在依赖这些引用的项目中用 `--no-plugins` 更新锁文件。** 这时 Composer 会写入它自己的路径引用，之后的源码变化不再改变 `composer.lock`，因此不会要求运行 `skernel build`，应用会继续使用旧源码的元数据。请在启用插件的情况下运行 `composer update`。
